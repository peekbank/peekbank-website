# Peekbank Website + Documentation

The Peekbank website serves our docs pages, the landing page, and the interactive
explorers under `/analyses`. It is a static [Astro](https://docs.astro.build/en/getting-started/) + [Starlight](https://starlight.astro.build/) site, styled with the [Nova theme](https://starlight-theme-nova.pages.dev/) and [Tailwind](https://tailwindcss.com/docs/styling-with-utility-classes).

The explorers are a separate Quarto project in `viz_src/` that also runs on its own with `quarto preview`.
`npm run build:viz` renders it and copies the result into the Astro site.

## Setup

You need [Node and npm](https://docs.npmjs.com/downloading-and-installing-node-js-and-npm).

In the repo's root, install dependencies with

```
npm i
```

To start the dev server, run:

```
npm run dev
```

The site is then reachable via `localhost:4321`. Updates you make to pages should immediately appear via hot reload.

Pages that depend on Redivis data (e.g. `/analyses`) stay empty in dev until the data is pulled (also needed for `npm run build`).

To pull in the data, you need:
* [uv](https://docs.astral.sh/uv/)
* [Quarto](https://quarto.org/docs/get-started/)
* a read-only Redivis token with the `data.metadata` scope: copy `.env.template` to `.env.local` and fill it in

Then pull the data and render the explorers:

```
npm run viz:pull
npm run build:viz
```

Rerun `build:viz` after changing the explorer code. To preview an explorer on its own, run `quarto preview` in `viz_src/`.

## Rough mapping of where to find things

| To change | Go to |
| :-- | :-- |
| a docs page | `src/content/docs/`; sidebar order is in `astro.config.mjs` |
| the landing page | `src/pages/index.astro`, `src/components/landing/` |
| a page outside the sidebar and llms.txt | `src/pages/` |
| the codebook | `src/data/codebook*.json` |
| the schema diagrams | `tools/`, see [Schema diagrams](#schema-diagrams) |
| a dataset explorer | `viz_src/`, see its README |
| the release the site shows | `viz_src/release.json` |
| styling | Tailwind in the components; Starlight overrides in `src/styles/global.css`; explorers in `viz_src/theme/` |
| the llms.txt export | the `starlightLlmsTxt` config in `astro.config.mjs`, `src/middleware.ts` |

## Locally generated files during dev

Some of the files (mostly data and build artefacts for the `/analyses` subpage) are autogenerated and rebuilt on every machine / during the CI process:

| Path | Created by | Used by |
| :-- | :-- | :-- |
| `viz_src/slices/` | `npm run viz:pull` | explorers, landing stats, How to Cite dataset table |
| `viz_src/releases.json` | `npm run releases:pull` (part of `viz:pull`) | release list on the Redivis page |
| `viz_src/_site/` | `quarto render` (part of `build:viz`) | `quarto preview` |
| `src/components/analyses/viz_autogen/`, `public/viz/` | `npm run build:viz` | `/analyses/*` |

The quarto explorers run in two places, which is why we locally copy the data slices to both:
- `quarto preview`serves them from `viz_src/_site/`
- the Astro site from `public/viz/`.

```
Redivis ──viz:pull──> viz_src/slices ──quarto render──> viz_src/_site/slices
                            └────────build:viz────────> public/viz/slices ──> dist/
```

## Schema diagrams

The diagrams in `public/diagrams/` are committed and not part of the build. Rerun `tools/render.sh` by hand when the schema changes; it needs [d2](https://d2lang.com/) and `python3`, but no token.
It reads the columns from Redivis, while the relationships between tables are declared in `tools/gen_schema_d2.py` and have to match `peekbankr/inst/peekbank-schema.json`.

## Deployment

Pushing to `main` deploys to GitHub Pages (`.github/workflows/deploy.yml`).
CI pulls the data itself, so the repo needs a read-only Redivis token with
`data.metadata` scope as an Actions secret named `REDIVIS_API_TOKEN`.
The slices are cached by the contents of `viz_src/release.json` and `scripts/*.py`; the release list is pulled fresh on every deploy.

## Oddities and little tips

* Redivis queries need the `data.metadata` scope even on public data, while plain table downloads work without it.
* The live site is served under `/peekbank-website/`, dev under `/`. A link starting with `/` works in dev and breaks live, so use relative links in pages and `import.meta.env.BASE_URL` in components. To check, build and preview with `ASTRO_BASE=/peekbank-website/` set for both commands.
* Site-only markup inside a docs page (diagrams, dropdowns) can be kept out of llms.txt by putting `data-mdast="ignore"` on its wrapping element.
* The Nova theme applies a 1rem top margin to various elements. If a row of elements is misaligned, set the (top) margin explicitly with Tailwind.
