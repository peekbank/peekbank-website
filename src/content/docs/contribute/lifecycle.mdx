## Raw data in peekbank_files

The lab sends the data (or a link to a data repository) to someone on the Peekbank team, who uploads it to <a href="https://stanford.redivis.com/datasets/frvk-5c922jwkx/files" target="_blank">peekbank_files</a> on Redivis. Each dataset has its own folder there, named after its identifier (for example `weaver_zettersten_2024`), holding the raw files.

## Import

The import process turns the raw data into preprocessed data in the Peekbank format. For each dataset, a collaborator writes a separate, scaffolded `import.R` script in <a href="https://github.com/peekbank/peekbank-data-import" target="_blank">peekbank-data-import</a>, which downloads the raw data from <a href="https://stanford.redivis.com/datasets/frvk-5c922jwkx/files" target="_blank">peekbank_files</a>, reshapes it (outputting one `.csv` per table of the schema) and validates the result. Next to the script, the dataset's `README.md` documents the import decisions.

The import scripts use some internal helper functions from <a href="https://github.com/peekbank/peekbankr" target="_blank">PeekbankR</a>.

Once the data passes validation, we perform an internal review step where another collaborator looks through the import script and the paper the data came from in tandem. Until then, a file named `ignored_by_pipeline_remove_after_review.txt` in the dataset's folder keeps it out of the pipeline and the releases. If no further issues are found, the reviewer deletes that file and commits the deletion, which makes the dataset part of the next release.

With a flag in the import script, the processed data and `README.md` can also be uploaded to <a href="https://stanford.redivis.com/datasets/frvk-5c922jwkx/files" target="_blank">peekbank_files</a>, into the special `_processed_data` folder under the dataset's identifier (creating e.g. `_processed_data/reflook_v4/trials.csv`). Releases do not use these uploads, but the [cached workflow](#testing-with-the-cached-workflow) for testing does, to allow for faster end-to-end testing of import changes.

## Ingestion

The ingestion builds a draft of the next release of <a href="https://stanford.redivis.com/datasets/a3v0-3drqa89kg" target="_blank">Peekbank on Redivis</a> from the raw data and the import code. It is triggered via a command in <a href="https://github.com/peekbank/peekbank-data-import" target="_blank">peekbank-data-import</a> (`./pbi ingest <release-name>`), which runs in Docker and pins both the raw data and the state of the import repository to the release. It downloads the raw data, reruns every import script and then combines the processed `.csv` files of all datasets into one set of tables, offsetting the row IDs to their position in the joined dataset. The process stops if any dataset fails to import or validate. Peekbank uses release names in the format \<YEAR\>.\<Incrementing Number\>.

Every dataset's `README.md` and raw data go into the release as files, in the `dataset_files` table under a folder named after the dataset. These files enable us to reproduce the ingestion if needed and allow PeekbankR to fetch versioned stimulus images and READMEs. Raw data that may not be shared publicly stays in a private Redivis dataset. The release holds a note in its place, that pins the version of the private dataset on Redivis the build used.

The ingest also creates an `aoi_timepoints_rle` table, a <a href="https://en.wikipedia.org/wiki/Run-length_encoding" target="_blank">run-length-encoded</a> version of `aoi_timepoints`, which is used by PeekbankR to cut transmission size. Similarly, the ingestion creates a `release_info` table with metadata, which has a single row with the release name of the dataset, the commit of <a href="https://github.com/peekbank/peekbank-data-import" target="_blank">peekbank-data-import</a> it was built from, and the version of the private raw data it used.

<summary>Testing with the cached workflow</summary>

Rerunning every import takes a while, so for quickly testing import changes there is a quicker way, depicted in the "Cached workflow for quick testing" tab above. `./pbi ingest <release-name> --cache` builds a draft from the cached `.csv` files uploaded to `_processed_data`. Such a draft records no import repository commit and is labelled as a test build on Redivis. Individuals with edit access on the Peekbank dataset on Redivis can read it with `peekbank("next")` in PeekbankR for testing purposes.

</details>

## Release

Releasing the draft with `./pbi release <release-name>` (or the Redivis interface) publishes it as a new release of the Peekbank dataset. Redivis numbers its versions on its own (e.g., `%REDIVIS_VERSION%`), so our `release_info` table is used to keep track of Peekbank release names (e.g., `%RELEASE%`). Previous versions stay available to keep old analyses reproducible. The list of supported releases can be seen on the <a href="../../peekbank/releases/" target="_blank">Releases</a> page.

## Access

End users have three ways to access the data of a release:

- <a href="../../start/dataaccess/" target="_blank">PeekbankR</a>, the R package most people use. It allows you to specify a release and read the tables from Redivis into your R environment.
- <a href="../../start/dataaccess/redivis/" target="_blank">Redivis</a> itself, where you can browse and query the tables in the browser or read them with one of its clients.
- This website, as it features <a href="../../analyses/accuracy/" target="_blank">interactive visualisations</a> that let you explore some analyses on the data directly in the browser.

Furthermore, certain elements of this website (e.g., the dataset list on the <a href="../../misc/howtocite/#current-datasets" target="_blank">Citation page</a>) are populated with data from the releases. These, as well as the analyses, don't query Redivis live. When the website is deployed, a Python script pulls the releases and turns them into compressed per-dataset JSON files that the browser loads.

## Corrections

When someone finds a problem in the data, it goes into the issue tracker of <a href="https://github.com/peekbank/peekbank-data-import" target="_blank">peekbank-data-import</a>. That dataset's import script is then fixed, and the corrected data reaches everyone with the next release.
