An overview of the peekbankr client and helpers. For full argument lists, see the <a href="https://peekbank.github.io/peekbankr/reference/index.html" target="_blank">full function reference</a>.

## Creating a Client

`peekbank()` returns a client pinned to one <a href="../../peekbank/releases/" target="_blank">Peekbank release</a>, through which most of peekbankr is used.

```r
pb <- peekbank("2026.1")
```

`peekbank_releases()` lists the releases you can pass. `"current"` takes the most recently published one.

## Tables

The client has one field per table in the [data schema](../../peekbank/dataschema/), each reachable three ways (here `trials`):

| | |
| --- | --- |
| `pb$trials` | the whole table, fetched once per session and reused after that |
| <code class="whitespace-nowrap">{"pb$subset$trials(...)"}</code> | narrowed by `dplyr` predicates |
| `pb$db$trials` | a `dbplyr` handle, transferred on `collect()` |

In addition to the fields described in the schema, `datasets`, `subjects`, `administrations`, `trials`, `trial_types` and `stimuli` also carry a `dataset_name` column when returned by peekbankr.

### Whole tables

`pb$<table>` returns the whole table as a tibble. It is downloaded once on first access and kept for the rest of the R session for subsequent use.

### Subsets

`pb$subset$<table>(...)` returns only the rows matching the `dplyr` predicates you pass. You can pass multiple predicates separated by comma, which are then combined with AND. A predicate can name the table's own columns and the columns of anything a row is uniquely linked to:

<SubsetColumns />

The result has only the table's own columns and is cached for the session.

**The timepoint tables** are filtered on the server before data transfer, limiting predicates to what can be <a href="https://docs.redivis.com/api/client-libraries/redivis-r/reference/redivis/redivisusdconnect_dbi#supported-dplyr-functions" target="_blank">translated to SQL</a>. Local variables are filled in automatically, but if you want to evaluate a function before sending it to the server (e.g. to compare some external values), you need to prefix with `!!`, e.g. <code class="whitespace-nowrap">{"age < !!max(local_ages)"}</code>, as the function would otherwise be sent to the server for translation.

All other tables are filtered locally and take any `dplyr` expression.

### Server-side queries

`pb$db$<table>` is a lazy `dbplyr` table on Redivis. `dplyr` verbs on it compile to SQL and run on the server, and the results are fetched on calling `collect()`.

```r
pb$db$aoi_timepoints |>
  dplyr::count(aoi) |>
  dplyr::collect()
```

`pb$db` also holds `aoi_timepoints_rle`, a compressed form of `aoi_timepoints`: one row per run of a constant AOI, starting at `t_norm` and `length` samples long.

### Auxiliary data

From release 2025.1 on, `datasets`, `subjects`, `administrations`, `trials`, `trial_types` and `stimuli` each carry a `*_aux_data` column holding JSON data on things recorded that don't fit into the schema, most notably <a href="https://mb-cdi.stanford.edu/" target="_blank">CDI scores</a> on `subjects`. The tables return the JSON as a raw string, so unpack before use:

```r
subjects <- pb$subjects |>
  unpack_aux_data()
```

## Client Fields

| Field | What it holds |
| --- | --- |
| `pb$release` | the Peekbank release this client is pinned to, e.g. `"2026.1"` |
| `pb$redivis_tag` | the Redivis version holding it, e.g. `"v1.4"` |
| `pb$tables` | the names of the tables in this release |

Printing the client shows the release it is pinned to and what is on it:

```r
pb
#> <peekbank> release 2026.1 (Redivis version v1.4)
#>   tables:  datasets subjects administrations trials trial_types stimuli
#>            aoi_region_sets aoi_timepoints xy_timepoints
#>   methods: clear_cache() images() query() readmes()
#>   subset:  $subset$<table>(<dplyr predicates>)
#>   db:      $db$<table> for a dbplyr handle, read on collect()
```

## Methods

### pb$query()

Runs BigQuery Standard SQL against the pinned release and returns a tibble. String comparison is case-sensitive. Results are cached for the session.

```r
pb$query("SELECT dataset_name, shortcite FROM datasets")
```

### pb$images()

Downloads the stimulus images to `<dir>/<dataset_name>/raw_data/<stimulus_image_path>` and returns a tibble with:

- one row per stimulus that has an image, in the requested datasets
- the columns of `pb$stimuli`, plus `local_image_path`: the path the image was saved to, or `NA` where the download failed

| Argument | Default | |
| --- | --- | --- |
| `datasets` | all datasets | names of the datasets to download images for |
| `dir` | {'"stimulus_data"'} | directory to save them to |
| `skip_existing` | TRUE | skip images already on disk |

```r
stimuli <- pb$images(datasets = "reflook_v4")
```

### pb$readmes()

Downloads the per-dataset READMEs, which record import decisions and dataset quirks, to `<dir>/<dataset_name>.md` and returns a tibble with:

- one row per requested dataset in the release
- the columns of `pb$datasets`, plus `local_readme_path`: the path the README was saved to, and `readme`: its text (both `NA` where the download failed)

| Argument | Default | |
| --- | --- | --- |
| `datasets` | all datasets | names of the datasets to download READMEs for |
| `dir` | {'"dataset_readmes"'} | directory to save them to |

```r
readmes <- pb$readmes(datasets = "pomper_saffran_2016")
```

### pb$clear_cache()

Drops this release's cached tables and query results.

```r
pb$clear_cache()
```

## Helper Functions

### peekbank_releases()

Returns a tibble with:

- one row per release `peekbank()` can be pinned to, most recently published first
- the columns `release`, `redivis_tag` (the Redivis version holding it) and `current` (`TRUE` for the one `"current"` resolves to)

```r
peekbank_releases()
```

### unpack_aux_data()

Parses every `*_aux_data` column of a table from its JSON string into a nested list column.

```r
subjects <- pb$subjects |>
  unpack_aux_data()
```

### cleanup_cdi_data()

Takes unnested CDI scores and checks them for duplicate scores of the same administration. Duplicates are reported with a warning and only the highest score is kept.

### populate_cdi_percentiles()

Adds the reference age and year used, along with gender-specific and general percentiles, to cleaned CDI scores.

### append_relative_cdi_scores()

Adds `cdi_relative`, the raw score as a share of the items on the instrument. Instruments with an unknown length get `NA`.

The CDI helpers work on the unnested scores in `subject_aux_data`:

```r
cdi <- pb$subjects |>
  unpack_aux_data() |>
  tidyr::unnest(subject_aux_data) |>
  dplyr::filter(!is.na(cdi_responses)) |>
  tidyr::unnest(cdi_responses) |>
  cleanup_cdi_data() |>
  populate_cdi_percentiles() |>
  append_relative_cdi_scores()
```
